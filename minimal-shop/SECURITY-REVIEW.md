# 安全验收记录（2026-09-25）

## 范围与状态

本记录只涵盖 `minimal-shop` 新项目及其隔离测试环境，不代表现有生产站点已完成修复。测试环境是本机 Go 程序连接到独立的 `shop_test` 数据库，以及服务器上的独立 Compose 项目 `minimal-shop-security-test`。服务器测试站只绑定 `127.0.0.1:18081`；未连接生产数据库、支付商户或真实卡密。

**当前状态：尚未批准生产切换。** 没有任何测试能够保证“没有漏洞”；以下证据说明已经验证的范围和仍需完成的上线门槛。

## 已验证

- `go test ./...`：使用可丢弃的 PostgreSQL `shop_test` 数据库，完整交易集成测试通过。测试包括注册登录、管理员 TOTP 与会话过期、上架导入、下单支付发卡、并发库存、卡密越权读取、伪造与重复回调、金额不符、旧支付通道回调、过期订单、CSRF、XSS 和单用户待支付订单上限。测试只创建并删除随机 schema。
- `go vet ./...`：通过。
- Linux 容器内 `CGO_ENABLED=1 go test -race ./internal/shop -count=1`：包含完整交易集成测试，未报告数据竞争。
- `govulncheck ./...`：应用可达漏洞 0，导入包漏洞 0；依赖模块层面有 1 条未调用的 `x/crypto/openpgp` 公告。上线前重新扫描。
- `FuzzProviderCallbacks` 20 秒约 37 万次、`FuzzProviderAmount` 20 秒约 30 万次：未发现崩溃。
- 隔离 Compose 实际启动：迁移容器完成建表，授权容器授予 `shop_app` 数据权限，运行容器健康检查返回 200。数据库端口未发布，HTTP 端口只绑定回环地址。`shop_app` 可读业务表，尝试 `CREATE TABLE` 被数据库拒绝。
- 使用 `ops/backup.sh` 生成备份，SHA-256 校验通过；在独立的 `shop_restore` 测试库恢复，查询到 9 张业务表，随后删除该恢复库。
- 对照 BEPUSDT `create-order` 收银台接口文档及其通知源码：签名字段、30 分钟超时及 `success` 回调响应已由本地测试覆盖。BEPUSDT 另一种交易接口的文档使用 `ok`；当前代码没有调用该接口。

## 已加固

- 支付回调在验签后核对支付单、订单、金额、币种、有效期与卡密预留关系；数据库事务保证重复通知不会重复发卡。异常付款只记录并交由人工核对。
- 生产模式禁用模拟支付，模拟模式要求回环站点地址；生产会话使用 Secure 的 `__Host-` Cookie，响应禁止缓存。管理员会话设置 30 分钟空闲时限。
- 单用户最多保留 3 个有效待支付订单，限制恶意占用库存。过期订单不再显示支付链接。
- Compose 把建表权限和站点运行权限拆开；运行容器只读、删除 Linux capabilities，并设置 `no-new-privileges`。
- 登录和注册限速仅接受来自明确配置的可信代理的 `X-Real-IP`；其他来源伪造该请求头不会改变限速身份。

## 上线前必须完成

1. 在隔离的预发布域名和独立测试商品上，分别实付易支付及 BEPUSDT 小额订单，记录完整创建订单、真实回调、金额核对、一次发卡、重复回调和退款或异常处理结果。当前没有沙箱凭据，因此模拟网关测试不能代替此项。
2. 用最终域名配置 HTTPS 反向代理，验证回调 URL 可达及代理传递的 `Host`、`Origin`、真实客户端 IP。将代理实际来源地址以精确 CIDR 配置为 `SHOP_TRUSTED_PROXY_CIDRS`，并让代理覆盖 `X-Real-IP`；在代理层对登录、注册、下单增加 IP 限速。
3. 使用独立的生产密钥和数据库口令，验证 `.env` 文件权限；对数据库备份及 `SHOP_CARD_KEY_HEX` 分别做离线备份和恢复演练，设置自动备份、保留期与失败告警。
4. 验证生产监控与告警：回调失败、支付异常、订单积压、数据库不可用和备份失败。安排独立复核人员检查支付与发卡逻辑，再安排灰度切换及回退步骤。
5. 上线前重新运行测试、依赖漏洞扫描和配置检查。新站不得直接使用现站数据库或真实卡密做测试。
